# UI 迁移与等价验证

## UI 策略

- `mixed`：推荐；品牌页面尽量保持布局意图、信息层级和状态，系统控件与平台交互原生化。
- `native`：业务语义保持一致，视觉与导航优先目标平台习惯。
- `visual`：视觉优先，明确自定义控件成本和不允许破坏的系统行为。

推荐值不是批准。把选定策略、允许的平台差异、截图条件和验收阈值放入设计，展示后取得用户确认。不要自动生成 Web 原型替换源端页面；只有额外需要原型且用户确认时才作为补充证据。

## 必备输入

结合 UI 代码/组件树/约束、真实资源/字体/主题令牌、状态机、截图/交互记录、目标组件库和授权设计稿。单张截图无法推断错误状态、异步时序、滚动、导航和无障碍。

每个 UI 状态记录组件、布局约束、内容条件、交互/禁用行为、键盘/焦点、安全区、无障碍和适配。无 UI 的契约允许数组为空，但注明原因，不编造页面。

## 适配清单

- dp/sp/pt 与字体度量不能简单照抄；比较视觉尺寸、基线、行高、字重和触摸区域。
- 检查安全区、系统栏、键盘遮挡、滚动/分页、横竖屏、不同屏幕尺寸和小屏。
- 检查浅/深色、大字体、长文本、多语言、RTL、对比度、图片比例和fallback。
- 检查返回键/交互返回、弹窗关闭、重复点击、输入焦点、朗读顺序、无障碍标签与缩放。
- 恢复资源授权与本地化，正确接入 Android 资源目录或 Xcode asset catalog/target；不要复制未经授权的字体。

## 验证矩阵

为每个范围内契约包含：主流程、空/加载/成功/失败/禁用状态、超时/弱网、重试/重复操作、退出/取消、前后台和恢复，以及相关适配条件。不适用项说明理由。

固定 mock 数据、时钟、随机种子、语言、主题与字号；记录两端设备/系统、窗口/安全区域、截图裁剪和坐标归一化策略。动态时间、头像等遮罩必须事先说明，不能遮住实际缺陷。像素尺寸不同先按批准规则归一化，不盲目拉伸。

截图可以核对组件树、几何、文字、颜色、资源和分区域图片差异；匹配阈值由具体任务确认，不给全项目通用“95%准确率”。对 native-substitute 区域单独按原生规则检查，不把允许差异当缺陷也不事后放宽标准。

行为采用相同事件序列和接口夹具，比较请求、状态转换、副作用、导航和持久化。交互、生命周期、性能与无障碍另做检查，图片相似不能证明这些通过。

## 可选工具与边界

Android 可用经授权 ADB、测试框架/UI Automator/Compose测试；iOS 可用经授权 Simulator/XCTest/XCUITest；跨端可使用真实安装的 Appium。先检查本机工具与 SDK，不假设任何服务、设备 ID、bundle ID 或端口。

现有 `ui_diff_skill` 可作为 Android/网页/UI层级比较的辅助；先确认其具体适配器和 iOS 输入支持，没有原生 iOS 能力时不要声称已完成跨端视觉对照。可采用截图和 XCTest证据；缺工具时报告未验证，不伪造数据。

安装、启动、模拟器开机/权限/清数据以及有状态 UI 自动化必须展示精确命令并取得本轮确认。截图/日志脱敏，禁止保存密码或真实身份信息。

## 判定

独立报告功能、视觉、交互/无障碍、集成各项结果。必要场景失败需返工；无法运行、只有单端证据或缺工具标 incomplete。通过结构校验或编译只能作为辅助证据，不能宣布功能/UI等价。
