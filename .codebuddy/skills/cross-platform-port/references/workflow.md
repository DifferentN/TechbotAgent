# 阶段、产物与交接协议

## 阶段闸门

| 阶段 | 前提 | 产物 | 出口 |
|---|---|---|---|
| intake | 用户迁移请求 | `scope.md`，任务 ID、方向、根目录、纳入/排除、初步验收 | 用户确认范围 |
| analysis | 配置有效、范围确认 | `source-analysis.md`、`target-analysis.md`、证据 | IR 草稿结构与引用通过 |
| specification | 双端分析 | `ir.json`、全状态 UI 说明、未知项 | 用户批准具体 IR 与 UI 策略 |
| design | 规格批准 | `design.md/json`、映射、切片、白名单、风险 | 用户批准具体设计和差异 |
| implementation | ready 校验、真实批准、写入许可 | 目标代码/测试、`implementation.md` | 必要本地检查通过，未通过项明确 |
| verification | 批准规格/设计与实现 | `verification.md/json`、夹具/证据 | 必要验收项通过或返工 |

所有任务产物位于配置 `artifact_root/<task-id>/`，默认 `porting/<task-id>/`。阶段状态写 `status.md`，包含当前阶段、产物版本、完成内容、批准引用、阻塞和下一步；总控单独维护。不要把流程产物混进现有 `demand/`、`architecture/` 或无关任务文档。

## 交接输入

每次委派提供：

- 任务 ID、方向、阶段、明确功能范围与排除项。
- 配置绝对路径、协调工作区、产物绝对路径。
- 源/目标平台、根目录、框架、SDK/最低系统版本、模块入口。
- 已检查的版本基线：Git commit；有未提交修改时增加相关文件内容摘要和差异范围。非 Git 项目采用文件摘要，禁止伪造 commit。
- 输入产物与批准记录、当前文档摘要、方案未决项。
- 允许读取目录、允许写入目录/文件、禁止操作与实际工具可用性。
- 本角色目标、验收条件、需要返回的证据与阻塞。

交接输出只返回：阶段结果、产物路径/版本、短证据、变更清单、执行过的命令与退出码、阻塞、下一步。异步启动确认不等于任务完成；等待实际结果再推进。缺输入时停止对应阶段，不用猜测补齐高风险规则。

## IR 与批准

`ir.schema.json` 固定功能与 UI 契约，`design.schema.json` 固定目标映射和修改范围。示例中的业务是合成“只读列表”，禁止直接当当前项目证据。为事实提供证据 ID，为推断提供依据，为未知提供待确认项。

批准记录包含 `status: pending/approved`、`record`（用户消息定位、时间和确认范围）与 `digest`。摘要由文档删除顶层 `approval` 后，按键排序、UTF-8、紧凑 JSON 序列化计算。使用工具计算，不手填摘要。设计中的 `source_ir_digest` 绑定整个 IR 的有效内容摘要。

总控展示真实规格/设计后取得用户确认，才记录批准；单独修改 JSON 不能授予操作权限。校验器无法鉴别确认记录真假，也不检查当前源码是否漂移，总控必须人工核实来源和当前基线。未提交修改不要清理或覆盖。

## verification.json 报告契约

报告至少包含：

- `task_id`、`direction`、`ir_digest`、`design_digest`、源/目标实际验证基线。
- `environment`：设备/模拟器、系统版本、语言、主题、字体缩放、数据夹具、工具版本与限制。
- `checks`：每项记录 ID、类别（build/behavior/ui/interaction/accessibility/integration）、IR 场景 ID、状态（passed/failed/blocked/not-run）、实际命令与工作目录、退出码或非命令观察说明、双端证据位置、预期、实际、缺陷 ID。
- `coverage`：范围内契约数、场景数、已执行数、通过数、失败数、阻塞/未运行数；报告分母与优先级，不用模型置信分数充当准确率。
- `differences`：批准的平台差异与发现的新差异，不能事后扩大允许差异。
- `verdict`：accepted/needs-work/incomplete；未运行必要检查时只能 incomplete。

本版本脚本校验配置/IR/设计，不自动校验报告或实际执行 SDK/截图工具。报告真实性和完成判定由独立验证器核实。构建通过只能证明该构建配置下可编译，不代表接口、生命周期或 UI 等价。

## 失败处理

定位理解错误、实现错误、规格遗漏、平台限制或环境缺失。理解/规格错误返回规格阶段；设计错误返回设计阶段；实现错误返回开发；环境缺失报告阻塞。禁止删除失败用例、放宽阈值或引入空实现来闭环。

审阅依赖和风险后再逐步扩大支持矩阵；支付、后台、多媒体、复杂动画和定制渲染不作为首版自动成功承诺。规范可复用，但两次反向迁移各自需要真实证据与批准，不能拿前一次结果自动批准反向转换。
